# TW VH Bot

Telegram-бот для работы с виртуальным хостингом Timeweb через публичный API. Позволяет авторизоваться под своим аккаунтом и посмотреть список сайтов, список доменов и баланс.

Бот развёрнут на виртуальном хостинге Timeweb и доступен для проверки: [@tw_vh_bot](https://t.me/tw_vh_bot)

Используется из хостинга: Python 3.10 (приложение через WSGI), MySQL (пользователи и шаги авторизации), SSL на домене `ch81104.tw1.ru`.

## Как проверить

1. Открыть [@tw_vh_bot](https://t.me/tw_vh_bot) и нажать **Запустить бота**
2. Ввести по требованию бота ключ API (получить ключ можно в поддержке Timeweb), логин и пароль от аккаунта. API ключ и пароль не будут сохранены в чате, а будут сразу же удалены. 
3. После авторизации появится меню: **Мои сайты**, **Мой баланс**, **Мои домены**, а также кнопка **Сменить аккаунт** (выйти и авторизоваться под другим аккаунтом).

>Если ввести неверные данные, бот сообщит об ошибке и предложит пройти авторизацию заново.

## Используемый стек

- Python 3.10
- pyTelegramBotAPI - работа с Telegram
- Flask - приём webhook на хостинге
- SQLAlchemy + PyMySQL - хранение данных пользователя в MySQL
- requests - запросы к API Timeweb
- python-dotenv - настройки из `.env`
- uv - управление зависимостями
- Cloudflare Workers - посредник между Telegram и хостингом 

## Как это работает

1. Локально бот работает через polling: сам спрашивает у Telegram новые сообщения.

2. На хостинге - через **webhook**. 

>Telegram и хостинг не могут обмениваться запросами, поэтому для обмена подключен посредник Cloudflare Workers. 

```text
Пользователь -> Telegram -> Cloudflare Worker -> хостинг (Flask -> бот)
бот -> Cloudflare Worker -> Telegram -> Пользователь
```

## Развернуть локально

### 1. Клонировать репозиторий

```bash
git clone https://github.com/varya-eltsova/tw-vh-bot.git
cd tw-vh-bot
```

### 2. Установить зависимости

Через uv:

```bash
uv sync
```

Или через pip:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Подготовить .env

Скопировать `.env.example` в `.env` и заполнить. Для локального запуска нужны `TG_TOKEN` и данные базы. `TG_API_URL` можно оставить пустым, если Telegram работает на вашем ПК или в вашей стране. В ином случае необходимо указать адрес посредника.

Если используется база на виртуальном хостинге, в панели управления нужно открыть к ней доступ со своего IP: **Базы данных MySQL** → **Добавить доступ**. `DB_HOST` в этом случае - IP-адрес сервера хостинга.

### 4. Создать таблицы в базе

```bash
python -m bot.db
```

### 5. Запустить бота

```bash
python -m bot.main
```

>Если у бота уже зарегистрирован webhook, polling работать не будет (Telegram вернёт `409 Conflict`).
Снять webhook:

```bash
python -c "from bot.main import tw_bot; tw_bot.remove_webhook()"
```

## Развертывание на виртуальном хостинге

1. Привязать к сайту домен с SSL-сертификатом. Telegram отправляет webhook только по HTTPS, а посредник пересылает запросы на сайт тоже по HTTPS. Здесь используется технический домен `ch81104.tw1.ru`: на нём сертификат Let's Encrypt установлен автоматически.
2. Клонировать проект **в папку сайта, рядом с `public_html`**: `~/<сайт>/tw-vh-bot`. В другие места домашней папки веб-приложение доступа не имеет.
3. Создать окружение и установить зависимости. `python3 -m venv` на хостинге не работает (нет `ensurepip`), поэтому через virtualenv:

   ```bash
   wget -O ~/virtualenv.pyz https://bootstrap.pypa.io/virtualenv/3.10/virtualenv.pyz
   python3 ~/virtualenv.pyz .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

4. Создать `.env` (`DB_HOST=localhost`, заполнить `TG_API_URL`, `WEBHOOK_URL`, `WEBHOOK_SECRET`) и закрыть доступ: `chmod 600 .env`.
5. Создать таблицы: `python -m bot.db`.
6. Скопировать `deploy/index.wsgi` и `deploy/.htaccess` в `public_html`, поправить пути в `index.wsgi` под свой аккаунт, выставить `chmod 755 index.wsgi`.
7. Создать Cloudflare Worker из `deploy/relay-worker.js` и задать ему переменные `BOT_ID` и `BOT_WEBHOOK_URL`.
8. Зарегистрировать webhook: `python -m bot.set_webhook`.

После обновления кода на сервере (`git pull`) нужно перезапустить приложение:

```bash
touch ~/<сайт>/public_html/index.wsgi
```

## Что пришлось решать

### Синхронный бот и webhook

На виртуальном хостинге долгие процессы завершаются через 800-1000 секунд, а Python-приложения запускаются только через WSGI. Поэтому бот не может постоянно висеть и опрашивать Telegram - только webhook: каждое сообщение приходит отдельным HTTP-запросом. По этой же причине выбран синхронный стек.

### Приложение не видело код проекта

Сначала проект лежал в `~/tw-vh-bot`, и любой запрос к `index.wsgi` возвращал 500, хотя из консоли тот же файл запускался без ошибок. Через тестовый `.wsgi`, который выводил ошибки прямо в ответ, выяснилось: веб-приложение на хостинге может читать и писать только внутри папки сайта. Проект перенесён в `~/<сайт>/tw-vh-bot`.

### Telegram недоступен с хостинга

Webhook не регистрировался. Проверка через `curl` на сервере показала: Google и API Timeweb доступны, а `api.telegram.org` - нет (таймаут на портах 443 и 80). `getWebhookInfo` показал, что и Telegram не может достучаться до сайта (`Connection timed out`). То есть сеть Telegram закрыта в обе стороны.

Решение - посредник на Cloudflare Workers, который видят и Telegram, и хостинг. Бот обращается к Telegram API через него (переменная `TG_API_URL`), а webhook зарегистрирован на адрес посредника. Чтобы посредником не могли пользоваться чужие боты, он пропускает запросы только для ID нашего бота.

### Список доменов

В документации API нет метода для списка всех доменов аккаунта. Рабочий адрес `GET /v1/accounts/{login}/domains` найден перебором версий API. Кириллические домены приходят в Punycode (`xn--...`), бот показывает их в обычном виде.

## Безопасность

- Пароль используется только для получения токена и не сохраняется. В базе хранятся только логин, ключ API и токен.
- Сообщения с ключом и паролем бот удаляет из чата сразу после получения.
- Webhook проверяет секретный заголовок `X-Telegram-Bot-Api-Secret-Token`. **Если секрет не задан, отклоняются все запросы.**
- Секреты хранятся только в `.env`, который не попадает в git.
- В логи не пишутся пароли, токены и ключи.

## Что можно улучшить

- Добавить шифрование токенов и API ключей в БД.  
- Токен бота проходит через Cloudflare Worker, а для безопасности лучше использовать сервер не виртуального хостинга, а облачный сервер (например, Timeweb Cloud), где доступен Telegram. 
- Добавить тесты.
- Улучшить архитектуру проекта: вынести из main.py хенделеры, клавиатуры (main_menu) и форматирование (format_...) в отдельные файлы.
- Вынести логику авторизации из обработчиков в отдельный слой для тестирования без Telegram.
- Добавить срок жизни для незавершенной авторизации.
